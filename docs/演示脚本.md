# 演示脚本（5–8 分钟，普通话，1080p）

给第九届传智杯录像用。主脚本对准 **AI大模型创新应用挑战赛**，总长约 7 分钟。报 **AI创新应用挑战赛** 时，用文末「加拍」替换第 6 段的后 40 秒，总长仍控制在 8 分钟以内。

口播可以按自己的说法改，画面顺序不要改：先看到拒绝，再看到确认后的模拟执行。三个故障都要出现。

## 录之前

- 分辨率 1920×1080，帧率 30 即可。麦克风环境安静。全程普通话。
- 终端和浏览器缩放到评委能看清命令。深色主题也可以，对比度要够。
- 仓库根目录，已执行 `cp .env.example .env`。`.env` 里不要填 Key。确认 `MOCK=1`。
- 另开一个只放本脚本的窗口，放在不录到的屏幕上；若只有一块屏幕，用提词器，不要让 `.env` 出现在录屏里。
- 准备两个终端标签：
  - 标签 A：演示命令
  - 标签 B：预先打开 `src/agent/graph.py` 里建图的那一段，大约在 `StateGraph` 附近
- 浏览器打开 Streamlit 本地页：`MOCK=1 streamlit run src/ui/app.py`，地址一般是 `http://localhost:8501`。公网 URL 还没有时，口播说明「公网地址部署后填进报名表」，不要念一个不存在的域名。
- 事先各跑一遍下面的命令，确认 ImagePull 的拒绝和模拟执行都符合脚本。不要在录像中途第一次发现依赖没装。

画面自检（开录前勾完）：

- [ ] 1080p，时长预留到 7 分钟上下，不短于 5 分钟、不超过 8 分钟
- [ ] 桌面没有密钥、kubeconfig、邮箱、聊天里的 Token
- [ ] 侧栏或命令行能看出 `MOCK=1`，LLM 为规则回退
- [ ] 先演示未确认被拒绝，再演示 `CONFIRM` 或 `--confirm YES`
- [ ] ImagePull 走完整路径；OOM、CrashLoop 各出现一次报告
- [ ] 结尾能看见仓库地址；已有公网 URL 时再念一遍 URL

## 时间轴

| 时间 | 画面 | 要让评委看到的结论 |
|---|---|---|
| 0:00–0:40 | README | 这是告警分诊 Agent，默认可离线演示 |
| 0:40–1:10 | 选场景 | 本次主路径是 ImagePullBackOff |
| 1:10–2:20 | CLI 或 UI 诊断 | 现象、根因、证据来自取证，不是空聊天 |
| 2:20–3:20 | 证据与 Runbook | RAG 命中 `imagepullbackoff`，命令仍是提案 |
| 3:20–4:40 | 确认门闩 | 不确认就拒绝；输入确认词后 Mock 模拟执行 |
| 4:40–5:40 | OOM 与 CrashLoop | 同一条流水线，动作 id 随故障变化 |
| 5:40–6:30 | 架构 | 图在诊断结束；apply 在图外 |
| 6:30–7:10 | 收尾 | 仓库、测试、公网地址的完成状态 |

### 0:00–0:40 打开 README

画面：仓库根目录的 `README.md`，停在标题和架构草图。

口播：

> 这个作品是一个 Kubernetes 告警分诊 Agent。值班时常见的问题不是再要一个聊天框，而是告警来了以后，把 Pod、事件和 Runbook 收成一份报告，并且把改集群的动作留在人工确认之后。
>
> 默认是 MOCK 模式。评委不需要 kubeconfig，也不需要模型 API Key。没有 Key 的时候，程序用规则模板出报告。

鼠标划过架构图里的 `collect → retrieve → diagnose`，停一下「人工确认」那一行。

### 0:40–1:10 选定 ImagePull

画面：切到 Streamlit。侧栏选 **ImagePullBackOff**。Namespace 保持 `default`，Pod 留空。

口播：

> 主演示走镜像拉取失败。Mock 数据里这个 Pod 叫 demo-imagepull，镜像 Tag 是一个不存在的 nginx 标签。真实集群可以用 demo 目录的清单注入同一类故障；今天不连集群，保证每一步都能复现。

若评委材料更适合命令行，这一段改为终端里准备好的命令，先不要按回车：

```bash
MOCK=1 python -m src.cli --scenario imagepull
```

### 1:10–2:20 跑诊断

画面：点击「运行诊断」，或回车执行上面的命令。等到报告出现。滚动到「现象」「根因判断」「关键证据」。

口播：

> 程序先取证，再检索，再写报告。报告标题是 ImagePullBackOff。证据里能看到 Waiting 原因、Failed to pull image，以及镜像名 nginx、冒号、this-tag-does-not-exist-xyz。
>
> 根因判断写的是镜像名或 Tag 不存在，或者仓库不可达、缺少拉取凭证。这些句子来自证据和 Runbook，不是凭空编的集群状态。页面上 LLM 显示未配置，这次走的是规则回退。接上兼容 OpenAI 的接口时，同一条流水线会改由模型按同样的结构写报告，修复动作仍然来自代码目录，不来自模型随手写的命令。

在证据里用鼠标点出 `ImagePullBackOff` 和那条不存在的镜像。

### 2:20–3:20 证据与 RAG

画面：继续往下，停在「参考 Runbook」和「修复方案（需人工确认）」。展开「原始证据」或 CLI 里的 Events 几行。若时间够，再打开 `runbooks/imagepullbackoff.md` 三秒。

口播：

> 检索是本地 TF-IDF，索引来自 runbooks 目录，不访问向量数据库。ImagePull 这次应命中 imagepullbackoff 这份 Runbook。
>
> 修复方案一节写的是提案。动作 id 是 fix-image，含义是把容器镜像改成 nginx 1.27。风险等级是中，标记为可回滚。下面的 kubectl 只供阅读，程序不会把这段文本丢进 shell。到这里为止，集群和 Mock 状态都还没有被修改。

### 3:20–4:40 输入确认，Mock 执行

这一段是全片的安全结论，不要剪掉「拒绝」那一下。

**界面路径（推荐，评委容易看懂）：**

1. 勾选 `fix-image`。文本框先空着。用鼠标指着灰色的「执行修复」。
2. 口播：

   > 按钮现在是灰的。文本框的标签是「输入 CONFIRM 后执行」。没输入这个词，界面不会调用执行函数。

3. 在文本框输入 `CONFIRM`（大写）。按钮变为可点。点击「执行修复」。
4. 停在「已模拟执行（MOCK=1，未连接真实集群）」上。

**若主路径用 CLI，在界面之前或之后补这三行，中间留出输出：**

```bash
MOCK=1 python -m src.cli --apply --action fix-image --scenario imagepull
MOCK=1 python -m src.cli --apply --confirm YES --action fix-image --scenario imagepull
```

口播：

> 第一行没有确认令牌，程序拒绝，并说明集群没有被修改。审计日志打在标准错误。第二行的 `--confirm` 只接受大写 YES。确认之后，因为 MOCK 等于 1，它只打印将要执行的命令，并把进程里的 Mock 镜像改成 nginx 1.27。这不是连上生产集群去改 Deployment。

不要在录像里演示 `MOCK=0` 的写操作。

### 4:40–5:40 带过 OOM 和 CrashLoop

画面：回到侧栏，选 **OOMKilled**，运行诊断。滚动到根因和动作 `bump-memory`，停留约 25 秒。再选 **CrashLoopBackOff**，运行诊断，停在 `fix-command` 约 25 秒。不必对这两条再点执行。

口播：

> 同一条图可以换故障。OOM 的 Mock 证据是 memory limit 64Mi、上次退出码 137、原因 OOMKilled。提案是 bump-memory，把 limit 调到 256Mi。这里要说明白：上调限制只能打断这次演示里的重启，查泄漏还得看应用。
>
> CrashLoop 的日志是找不到配置文件，重启次数已经很高。提案是 fix-command，把启动命令换成一段健康休眠，并去掉探针，用来让 Pod 离开 CrashLoopBackOff。演示命令不是生产配置修复。两个动作都仍然要人工确认。

### 5:40–6:30 架构

画面：切到 `README.md` 的架构图，或 `src/agent/graph.py` 里 `collect → retrieve → diagnose` 的边。不要大段滚动代码。

口播：

> 编排优先用 LangGraph，三个节点按这个顺序连死。导入失败就用同样顺序的 Python 函数。诊断节点只写报告和提案。
>
> 执行在图的外面，入口是命令行的 `--apply` 或界面上的按钮，两边都进同一个 apply 函数。令牌不对、动作 id 不在目录里、名字不合法，都会拒绝。真实集群路径要等 MOCK 关掉并且确认通过之后才会走，优先用 Kubernetes 的 JSON Patch，而不是拼接 shell。

### 6:30–7:10 收尾

画面：回到 README 顶部的仓库说明，或提交清单的「状态一览」。若公网 URL 已经可用，浏览器地址栏停两秒。

口播：

> 仓库是公开的，README 里有环境变量模板和 Mock 命令。测试在 tests 目录，用 pytest 跑，覆盖诊断、拒绝未确认的修复，以及界面按钮的禁用条件。
>
> 作品对应的岗位是云原生和 SRE：先取证，再按 Runbook 缩小范围，变更默认关闭。在线演示地址和录像链接填在报名表里。谢谢。

公网地址还没部署时，把最后两句换成：

> 在线演示我会部署到公网后再把 URL 填进报名表。本地这条 Mock 路径就是评委不配集群时的复现方式。谢谢。

## 创新应用赛道加拍（替换 5:40 之后约 40 秒）

画面：打开 `recordings/prompts/02-增加人工确认修复门闩.md`，滚动到人类提示里「不要把 apply 放进 LangGraph」和「command 只给人看」两句。再切回灰色按钮 5 秒。

口播：

> 如果看协作过程：修复门闩是我先写清约束，再让助手改目录、apply 和测试。约束包括诊断图里不放执行节点、命令文本不进 shell、未确认必须拒绝。画面上这个灰色按钮就是那条约束的结果。仓库里的 prompts 目录目前是模板，正式提交我会换成自己的对话导出。

然后接「架构」剩余两句和收尾。整段仍不要超过 8 分钟。
