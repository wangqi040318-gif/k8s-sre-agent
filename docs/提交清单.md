两次提交能看出「先诊断、后确认修复」的顺序，但单次体积大。校内通知要求提交历史细到「一次核心对话或一个功能模块」，评委若按这个标准看，可能觉得粒度偏粗。

处理办法：

- 不要 `git rebase`、不要 `filter-branch`、不要 force-push。已公开的历史保持不动。
- 从现在起，文档、Runbook、UI 文案按小步提交。
- 报 **AI创新应用挑战赛** 时，用真实 Prompt 快照和视频里的协作片段说明开发顺序。快照是过程证据，不能靠改写 Git 补出来。

## 已完成的可演示行为

评委不配集群、不配 API Key 时，下面几条应当成立：

```bash
cp .env.example .env
python -m src.rag.ingest
MOCK=1 python -m src.cli --scenario imagepull
MOCK=1 python -m src.cli --apply --action fix-image --scenario imagepull
MOCK=1 python -m src.cli --apply --confirm YES --action fix-image --scenario imagepull
MOCK=1 streamlit run src/ui/app.py
pytest -q
```

不带 `--confirm` 的 `--apply` 会拒绝，不改 Mock 状态。带 `--confirm YES` 的那条打印「已模拟执行」。Streamlit 里要在文本框输入 `CONFIRM`，「执行修复」才会从禁用变为可点。

演示故障（确认后才改 Mock，未确认一律拒绝）：

| 场景 | 动作 id | 确认后的演示效果 |
|---|---|---|
| ImagePullBackOff | `fix-image` | 镜像改为 `nginx:1.27` |
| OOMKilled | `bump-memory` | memory limit 调到 `256Mi` |
| CrashLoopBackOff | `fix-command` | 启动命令改为健康休眠，并去掉探针 |
| Pending / 无法调度 | `relax-scheduling` | 降低 requests/limits，去掉错误的 nodeSelector 与 affinity |
| ConfigMap 挂载失败 | `create-config` | 创建 ConfigMap `app-config`，不覆盖已有键，不写 Secret |
| 探针未就绪 | `fix-probe` | 探针改为 `/` 与端口 `80`，不删除探针 |
| Service 无 Endpoints | `fix-selector` | Service `demo-web` 的 selector 改为 `app=demo` |
