# Prompt 快照模板 02：增加人工确认修复门闩

> **模板，不是真实对话导出。** 说明见 `01-脚手架诊断Agent.md` 顶部。报名 AI创新应用挑战赛前，用真实会话替换本文件。不要在模板里填写密钥。

## 这次协作要解决的问题

诊断报告已经能提出 kubectl 命令，但命令只是文字。作者要求增加「可以执行」的路径，同时保证默认不改集群，模型也不能自己发明一条命令就拿去跑。

## 人类提示（示例）

```text
在现有诊断 Agent 上增加修复，但必须守住这些约束：

- 诊断图仍然只有 collect → retrieve → diagnose。不要把 apply 放进 LangGraph。
- 报告里的 remediation 来自代码目录，不要采用模型自由生成的命令。
- 每条动作包含 id、description、command、api_op、risk_level、reversible。
- command 只给人看。执行使用 api_op。禁止把整段命令丢进 shell。
- 未确认时 apply 必须拒绝，并且不修改 Mock 状态。
- CLI 的 --confirm 只接受大写 YES。交互提示的文案是「输入 CONFIRM 后执行」，只接受原样 CONFIRM。
- 未知动作 id、非法命名空间、动作和场景不匹配，全部拒绝。
- 每次尝试（含拒绝）打审计日志，logger 名 src.remediation，输出到 stderr。
- MOCK=1 时确认后只打印命令并更新进程内状态。
- MOCK=0 时优先用官方 Python 客户端做 JSON Patch；客户端不可用才退回参数数组形式的 kubectl，且 shell=False。
- 请补测试：诊断本身不 apply；未确认拒绝；YES 模拟成功；交互输错拒绝。
```

## 助手回复要点（示例）

- 动作目录放在 `src/remediation/catalog.py`：`fix-image`、`bump-memory`、`fix-command`。
- 门闩放在 `src/remediation/apply.py`：`is_explicit_confirm` 只认 `YES` 与 `CONFIRM`。
- 真实集群路径放在 `src/remediation/live.py`，名称校验通过后才调用 API。
- `node_diagnose` 末尾调用目录函数，把提案写进 Markdown 和 JSON；函数内不调用 `apply_action`。
- CLI 把 `--apply` 分到另一条分支。没加 `--apply` 时即使带了 `--confirm` 也只诊断，并向 stderr 说明本次不改集群。
- 测试放在 `tests/test_remediation.py`，用 `monkeypatch` 避免碰到真实集群。

## 人类追问（示例）

```text
模型如果在正文里写了一条 kubectl delete ns，报告里的 remediation 数组会被换成这条吗？
```

示例中的答复：不会。`_ensure_remediation` 在模型文本返回之后，用目录结果覆盖 `report_json["remediation"]`。测试 `test_llm_text_cannot_replace_catalog_actions` 固定住这个行为。
